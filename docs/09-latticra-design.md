# Module 9 — Latticra Design

## Purpose

This module connects the course foundations to the design of the Latticra Operating System and the Latticra Programming Language.

## Core questions

- What kind of system is Latticra trying to become?
- How do operating systems and programming languages shape each other?
- What does trustworthy computing mean in practice?
- How can project claims stay evidence-bound?

## Key ideas

Latticra should be studied as a systems design project. A serious computing system requires clear goals, disciplined implementation, security awareness, documentation, testing, and restraint in public claims.

## Topics

- System identity
- OS/language co-design
- Command environments
- Trustworthy computing
- Defensive defaults
- Evidence-bound development
- Documentation as engineering
- Capstone proposal writing

## Exercise

Write a one-page Latticra design note. Choose one system feature and explain:

1. What it should do
2. Why it matters
3. What risks it introduces
4. How it could be tested
5. What claims can honestly be made today

## Capstone

Create a small systems design proposal that connects at least three course areas, such as C, operating systems, programming languages, and security.
