# Capstone Project

The capstone project completes **Latticra — Foundations of Computer Science**.

## Purpose

The capstone asks you to connect several course areas into one coherent systems project.

You do not need to build a full operating system or programming language. The goal is to show that you can reason like a systems-minded computer scientist.

## Choose one capstone track

### Track A — Tiny Interpreter

Design and optionally implement a tiny programming language.

Required components:

- Language purpose
- Syntax examples
- Token list
- Parsing strategy
- Evaluation rules
- Error examples
- Security or safety notes

Optional implementation:

- Interpreter in C, Python, JavaScript, Rust, Go, or another language

### Track B — Command Shell Model

Design a small command environment inspired by operating systems and Latticra.

Required components:

- Command list
- Input format
- Output format
- Error handling
- File interaction model
- Permission or safety model
- Example session transcript

### Track C — Filesystem Design Sketch

Design a small filesystem or virtual filesystem model.

Required components:

- File and directory model
- Path rules
- Metadata
- Permissions
- Read/write behavior
- Failure cases
- Security considerations

### Track D — Secure Notes System

Design a simple note-taking program with security posture.

Required components:

- Assets
- Threat model
- Data format
- Access model
- Failure modes
- Testing plan
- Honest security claims

### Track E — Latticra Design Proposal

Write a formal design proposal for one Latticra feature.

Required components:

- Feature purpose
- User model
- System model
- Language or OS relationship
- Security model
- Testing evidence needed
- Current status and next steps

## Required deliverables

Every capstone must include:

1. `README.md` or design document
2. System diagram or text model
3. At least five examples
4. Threat model or risk section
5. Testing or validation plan
6. Reflection connecting the work to at least three modules

## Evaluation rubric

| Area | Excellent |
| --- | --- |
| Conceptual clarity | The project explains what it does and why it matters |
| Systems thinking | The project connects code, memory, OS, language, or security ideas |
| Technical honesty | Claims are specific, limited, and evidence-bound |
| Examples | The project includes useful examples and failure cases |
| Security posture | Risks and assumptions are named clearly |
| Documentation | A reader can understand the project without guessing |

## Capstone reflection prompts

Answer these at the end:

1. Which course modules did this project use?
2. What did you understand better after building or designing it?
3. What was harder than expected?
4. What would you test next?
5. What claim can you honestly make about the project today?

## Completion standard

The capstone is complete when a reader can understand the project, run or inspect its examples, identify its assumptions, and see how it connects to the course arc.
