# Module 8 — Security

## Purpose

This module introduces security as a core discipline of computer science and systems design.

## Core questions

- What does it mean for a system to be secure?
- What is a threat model?
- Why do memory safety, permissions, and isolation matter?
- How should builders make responsible security claims?

## Key ideas

Security is not a feature added at the end. It is a design posture. Secure systems require careful assumptions, clear boundaries, defensive defaults, and evidence.

## Topics

- Threat modeling
- Attack surface
- Least privilege
- Memory safety
- Input validation
- Isolation
- Filesystem permissions
- Defensive programming
- Secure documentation
- Evidence-bound claims

## Exercise

Create a threat model for a simple note-taking program. Identify assets, possible attackers, attack surfaces, and mitigations.

## Latticra connection

Latticra security claims should be specific, tested, and documented. The course should train learners to separate aspiration from proof.
